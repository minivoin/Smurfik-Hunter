# Охотник на смурфиков

Ищет в Steam аккаунты, которые, скорее всего, принадлежат одному и тому же
человеку: основной профиль и его «смурфы» / твинки.

Две функции:

1. **Первичный анализ профиля** — по ссылке, за пару секунд: балл 0..100 и
   разбивка по проверкам.
2. **Поиск смежных аккаунтов** — обход графа друзей, 40–120 секунд: кто из
   окружения действительно похож на цель.

Инструмент состоит из четырёх частей:

| Часть | Что делает |
| --- | --- |
| Java-ядро (`com.papasmurf`) | ходит в Steam API, считает баллы и похожесть |
| Java-API (`com.papasmurf.web`) | отдаёт результат по HTTP в JSON |
| Python-бот (`bot/`) | ссылки в чате, команды `/profile`, `/related` и `/history` |
| Сервис истории (`history/`) | сохраняет итоги поисков в SQLite, отдаёт историю и статистику |

---

# Функция 1: первичный анализ профиля

Быстрая проверка одного аккаунта: два запроса к Steam, без обхода графа.
Показывает, стоит ли вообще копать дальше.

Максимум — 100 очков:

| Проверка | Макс. | Когда начисляется |
| --- | --- | --- |
| Возраст аккаунта | 30 | моложе 3 лет, линейно: 30 очков при 0 месяцев → 0 при 36 |
| Количество друзей | 15 | меньше 7 друзей; 5 очков, если друзей больше 150 |
| Аватар | 10 | стандартная картинка Steam |
| Друзья «Дня 1» | 20 | 20 очков за ≥3 друга, добавленных в первые 48 ч после регистрации, 15 за 1–2 |
| Плотная пачка | 25 | сколько друзей добавлено за 1 / 2 / 3 дня: ≥10 → 25, ≥7 → 20, ≥5 → 15, ≥3 → 10 |

Вердикты:

| Балл | Вердикт |
| --- | --- |
| ≥ 65 | «Похоже на смурф» |
| 45–64 | «Подозрительный аккаунт» |
| < 45 | «Обычный аккаунт» |

Для калибровки на реальных данных: свежий альт с 6 друзьями набрал **57.5**,
а основной аккаунт 2019 года — **10.0**.

**Оговорка.** Это эвристика по открытым данным Steam, а не доказательство.
Старый аккаунт тоже может быть смурфом, а новый — просто новым. Поэтому вторая
функция смотрит не на профиль, а на окружение.

# Функция 2: поиск смежных аккаунтов

1. **Сбор данных.** От целевого профиля берётся список друзей, затем профили и
   списки друзей этих друзей (глубина настраивается). Запросы к Steam идут с
   паузой 0.8 с, чтобы не получить 429.
2. **Признаки пары аккаунтов:**
   - `sharedFriends` — доля меньшего списка друзей, которая совпала;
   - `coAdd` — насколько синхронно аккаунты добавляли общих друзей;
   - `creation` — близость дат регистрации;
   - `directFriend` — состоят ли аккаунты в друзьях друг у друга;
   - `profile` — совпадение аватара и похожесть ников;
   - `burst` — «залповый» набор друзей (круг собран за один вечер).
3. **Скор.** Взвешенная сумма сигналов, 0..1. **Это схожесть, а не
   вероятность**: 0.45 значит «похожи», а не «45 % шанс, что это он».
4. **Группа.** Кандидат попадает в итоговую группу, только если он похож
   (≥ `ADD_THRESHOLD`) **на всех** текущих участников. Поэтому человек, который
   просто вращается в том же круге друзей, остаётся снаружи: с целью он похож,
   а с остальными участниками — нет.

### Веса сигналов

| Сигнал | Вес |
| --- | --- |
| `sharedFriends` | 0.55 |
| `coAdd` | 0.20 |
| `creation` | 0.10 |
| `directFriend` | 0.05 |
| `profile` | 0.05 |
| `burst` | 0.05 |

Формула `shared`:

```
overlap = common / min(sizeA, sizeB)      # доля меньшего списка
support = common / (common + 2)           # сколько общих друзей вообще есть
shared  = overlap * support
```

`support` не даёт паре с 1 общим другом из 1 получить идеальную схожесть.

### Пороги

| Константа | Значение | Смысл |
| --- | --- | --- |
| `ADD_THRESHOLD` | 0.40 | с этого скора кандидат может попасть в группу |
| `DISPLAY_THRESHOLD` | 0.15 | ниже этого кандидаты не показываются |
| `SUPPORT_FRIENDS` | 2.0 | сглаживание в формуле `shared` |
| `MAX_REPORTED` | 8 | сколько кандидатов выводится в отчёте |

**Честная оговорка.** Веса и пороги подобраны вручную на четырёх реальных
аккаунтах (три «своих» и один друг), а не обучены на размеченной выборке.
На этих данных допустимое окно порога — примерно `(0.34, 0.42]`: при 0.34 в
группу попадает друг, при 0.42+ распадается часть настоящих альтов. На других
профилях порог, возможно, придётся подкрутить. Это эвристика, а не машинное
обучение, и она не доказывает принадлежность — только указывает направление.

## Как всё связано

Независимые процессы, которые общаются по HTTP (локально — на localhost,
в Docker — по внутренней сети):

```
Discord  --сообщение со ссылкой-->  bot.py  --POST /api/v1/profile-->  ApiServer (Java)
         <--эмбеды с результатом--          <--------JSON ответ--------
                                                                          |
                                                                          +--> Steam Web API
                                                                          |
                                                              ProfileAnalyzer (0..100)
                                                              SamePersonDetector (граф)

bot.py  --POST /api/v1/history-->  history (FastAPI + SQLite)  -->  history.db
```

1. Пользователь кидает ссылку — **бот** вытаскивает её из текста.
2. Бот делает `POST http://127.0.0.1:8080/api/v1/profile` с этой ссылкой.
3. **Java-сервер** разрешает ссылку в SteamID64, идёт в Steam Web API за
   профилем и списком друзей, считает балл и возвращает JSON.
4. Бот рисует из JSON эмбеды. Тяжёлый поиск смежных аккаунтов — отдельный
   запрос `POST /api/v1/detect`, его запускает кнопка.
5. После удачного поиска бот отправляет итог в **сервис истории**
   (`POST /api/v1/history`). Там он остаётся после перезапуска Java и бота.

Бот не знает, как считать похожесть, — он только показывает. Поэтому ту же
ручку можно дёргать curl-ом, из Postman или из другого клиента, и результат
будет тот же.

### Два ключа — не путать

| Ключ | Зачем | Где взять |
| --- | --- | --- |
| `STEAM_API_KEY` | Java ходит в Steam за профилями и друзьями | https://steamcommunity.com/dev/apikey |
| `DISCORD_TOKEN` | Python-бот входит в Discord | https://discord.com/developers/applications |

Это разные сервисы. Steam-ключ боту не нужен, а Discord-токен не нужен Java.

### Как получить Discord-токен и пригласить бота

1. Откройте https://discord.com/developers/applications → **New Application**.
2. Слева **Bot** → **Reset Token** → скопируйте значение в `.env`
   (`DISCORD_TOKEN=...`). Токен показывают один раз; если потеряли — Reset Token.
3. Там же, в **Privileged Gateway Intents**, включите **MESSAGE CONTENT INTENT**
   (нужен, чтобы бот видел ссылки в обычных сообщениях).
4. Слева **OAuth2 → URL Generator**: scopes `bot` и `applications.commands`,
   permissions — `Send Messages`, `Embed Links`, `Read Message History`.
   Скопируйте ссылку, откройте её и добавьте бота на свой сервер.

- Java 21 (`java -version`)
- Maven
- Python 3.10+ — только для Discord-бота

## Настройка

Создайте в корне файл `.env`:

```dotenv
STEAM_API_KEY=ваш_ключ_steam
DISCORD_TOKEN=токен_бота              # только для бота
API_BASE_URL=http://127.0.0.1:8080    # только для бота
HISTORY_BASE_URL=http://127.0.0.1:8000  # необязательно: сервис истории (только для бота)
DISCORD_GUILD_ID=123456789012345678   # необязательно: мгновенная синхронизация команд
DISCORD_LINK_AUTODETECT=1             # необязательно: анализ ссылок из чата (по умолчанию включён)
```

Ключ Steam берётся на https://steamcommunity.com/dev/apikey.

```powershell
mvn -q -DskipTests compile
mvn -q dependency:build-classpath "-Dmdep.outputFile=target/cp.txt"
$cp = "target\classes;" + (Get-Content target\cp.txt -Raw).Trim()
java -Dstdout.encoding=UTF-8 -cp $cp com.papasmurf.Main 76561198890900243 2
```

Аргументы: `Main <SteamID64> [глубина 1..3] [only-group]`.
Флаг `only-group` скрывает неподтверждённых кандидатов.

В первом терминале:

```powershell
powershell -ExecutionPolicy Bypass -File run-api.ps1
```

Скрипт сам соберёт проект, посчитает classpath и запустит сервер. Сборка
занимает пару секунд, потом в консоли появится `Smurfik-Hunter API запущен`.

```powershell
mvn -q -DskipTests compile

$cp = "target\classes;" + (Get-Content target\cp.txt -Raw).Trim()
```

Адрес по умолчанию — `http://127.0.0.1:8080`, меняется через `API_HOST` и

### Ручки

| Метод | Путь | Описание |
| --- | --- | --- |
| `GET` | `/health` | жив ли сервер и видит ли он ключ Steam |
| `GET` | `/api/v1/profile/{profile}` | первичный анализ |
| `POST` | `/api/v1/profile` | то же, тело: `{"steamId": "..."}` |
| `GET` | `/api/v1/detect/{profile}?depth=2` | смежные аккаунты |
| `POST` | `/api/v1/detect` | то же, тело: `{"steamId": "...", "depth": 2}` |

## Discord-бот

Во втором терминале (Java-API уже должен быть запущен):

```powershell
powershell -ExecutionPolicy Bypass -File run-bot.ps1
```

Скрипт проверит Python, при необходимости поставит `discord.py` и `aiohttp`,
проверит токен в `.env` и запустит бота.

Вручную то же самое:

```powershell
python -m pip install -r bot/requirements.txt
python bot/bot.py
```

### Как пользоваться

**Просто отправьте ссылку в чат.** Бот найдёт её в сообщении, сделает первичный
анализ и покажет карточку с баллом и кнопкой «Найти смежные аккаунты». Кнопка
запускает тяжёлый поиск по тому же профилю и публикует результат отдельным
сообщением — карточка анализа остаётся на месте.

Команды:

| Команда | Что делает |
| --- | --- |
| `/profile <ссылка>` | первичный анализ + кнопка |
| `/related <ссылка> [depth]` | сразу поиск смежных аккаунтов |
| `/history <SteamID64>` | последние проверки профиля из сервиса истории |

Результат каждого удачного `/related` и нажатия кнопки сохраняется в историю
(если сервис истории запущен). Это не влияет на ответ в чате: история —
вспомогательная, при её недоступности бот просто ничего не сохраняет.

Бот только рисует то, что посчитал Java. В результатах поиска сначала идёт
карточка с итогом, потом блок **«ОДИН ЧЕЛОВЕК (подтверждено)»**, затем —
отдельно — **«ПОХОЖИ НА ЦЕЛЬ, НЕ ПОДТВЕРЖДЕНЫ»**. Разделение принципиальное:
иначе случайный знакомый в общем списке выглядит как найденный альт.

### Intent для чтения ссылок

Чтобы бот видел ссылки в обычных сообщениях, включите
**MESSAGE CONTENT INTENT** в Discord Developer Portal → ваш бот → Bot →
Privileged Gateway Intents. Без него Discord не отдаёт текст сообщений.

Если включать не хочется, поставьте в `.env` `DISCORD_LINK_AUTODETECT=0` —
бот запустится, но будет реагировать только на `/profile`, `/related` и
`/history`.
При включённом intent без разрешения в портале бот не стартует и напишет об
этом в консоль.

Чтобы команды появились сразу, укажите `DISCORD_GUILD_ID` (id вашего сервера).
Без него Discord регистрирует глобальные команды до часа.

## История и статистика

Кеш Java живёт 30 минут и умирает при перезапуске. История — постоянная:
она показывает, что находили раньше, сколько раз проверяли профиль и сколько
групп подтвердилось. Это ещё и материал для оценки качества алгоритма.

За историю отвечает отдельный сервис `history/` на Python (FastAPI + SQLite).
Бот присылает в него итог каждого удачного поиска смежных аккаунтов; сервис
хранит только итог (не списки друзей) и отдаёт его по HTTP. Если сервис
недоступен, бот продолжает работать — просто не сохраняет историю.

| Метод | Путь | Что делает |
| --- | --- | --- |
| `POST` | `/api/v1/history` | сохранить результат поиска |
| `GET` | `/api/v1/history?steamId=…&limit=10` | последние проверки профиля |
| `GET` | `/api/v1/stats` | всего проверок, среднее время, топ профилей, сколько нашлось групп |
| `GET` | `/health` | жив ли сервис и открывается ли база |

В базе одна таблица `checks`: время проверки, SteamID64, ник, глубина, состав
группы и её уверенность, число проверенных кандидатов, время поиска и признак
«из кеша». Ничего лишнего — ни друзей, ни токенов.

### Команда бота

`/history <SteamID64>` показывает карточку с последними проверками профиля:
время (UTC), размер группы и уверенность, число кандидатов, время поиска и
глубина. Принимается только номер (17 цифр) или ссылка
`.../profiles/7656119…`; красивую ссылку `.../id/имя` сервис не принимает,
потому что хранит только номера.

### Примеры

```powershell
# сохранить результат (так делает бот)
Invoke-RestMethod -Method Post "http://127.0.0.1:8000/api/v1/history" `
  -ContentType "application/json" -Body '{
    "steamId": "76561198890900243",
    "seedName": "Черепаха Хлофф",
    "depth": 2,
    "group": ["76561198890900243", "76561198740323709"],
    "groupConfidence": 0.422,
    "candidatesChecked": 21,
    "durationMs": 61234,
    "cached": false
  }'

# история профиля
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/history?steamId=76561198890900243"

# агрегаты
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/stats"
```

Ответ `/api/v1/stats` (сокращён):

```json
{
  "ok": true,
  "totalChecks": 12,
  "freshChecks": 9,
  "cacheHits": 3,
  "checksWithGroup": 5,
  "uniqueProfiles": 7,
  "avgFreshDurationMs": 48210,
  "lastCheckedAt": "2026-11-19T12:34:56+00:00",
  "topProfiles": [
```

### Локальный запуск

Сервису не нужны ни Steam-ключ, ни Discord-токен:

```powershell
powershell -ExecutionPolicy Bypass -File run-history.ps1
```

Скрипт сам проверит Python и поставит `fastapi`/`uvicorn`, если их нет. Вручную
то же самое:

```powershell
python -m pip install -r history/requirements.txt
python -m uvicorn app:app --app-dir history --host 127.0.0.1 --port 8000
```

База по умолчанию — `history/data/history.db`, путь меняется через `HISTORY_DB`.
Порт и адрес меняются через `HISTORY_PORT` и `HISTORY_HOST` в `.env`.
Оффлайн-проверка всех ручек: `python history/check_api.py`.

## Запуск через Docker

Нужен Docker Desktop (на Windows — с включённым WSL2). Docker сам соберёт
Java-API, бота и сервис истории и поднимет их в одной внутренней сети — вручную
ничего запускать не надо.

```powershell
# собрать образы и запустить в фоне
docker compose up --build -d

# смотреть логи
docker compose logs -f api
docker compose logs -f bot
docker compose logs -f history

# остановить
docker compose down
```

| Сервис | Образ | Что делает |
| --- | --- | --- |
| `api` | `smurfik-hunter-api` | Java-API, внутри сети слушает `0.0.0.0:8080` |
| `bot` | `smurfik-hunter-bot` | Discord-бот, ходит на `http://api:8080` и `http://history:8000` |
| `history` | `smurfik-hunter-history` | история и статистика: FastAPI + SQLite |

Что важно знать:

- `.env` читается с хоста и **в образ не копируется** — он исключён в
  `.dockerignore`. Заполните `STEAM_API_KEY` и `DISCORD_TOKEN` до первого
  запуска, иначе контейнеры поднимутся, но анализ и вход не заработают.
- API проброшен как `127.0.0.1:8080:8080` — доступен только с этой машины.
  Наружу его без авторизации выставлять нельзя.
- Бот стартует по `depends_on: service_healthy`, то есть после того как
  `/health` уже отвечает. Гонки «бот проснулся раньше API» нет.
- Кеш результатов живёт в памяти контейнера `api`. `docker compose restart api`
  его очищает — следующий поиск снова займёт около минуты. История живёт
  отдельно и перезапусков Java не боится.
- База истории лежит на named volume `history-data` и переживает пересборку и
  `docker compose restart history`. Удалить её можно только явно:
  `docker compose down -v`.
- Бот ждёт от сервиса истории только запуска контейнера (`service_started`),
  а не здоровья: если история упала, бот всё равно работает, просто не
  сохраняет проверки.
- Внутри контейнера бота `API_BASE_URL` переопределён на `http://api:8080`,
  а `HISTORY_BASE_URL` — на `http://history:8000`: `127.0.0.1` из `.env` там
  означал бы сам контейнер бота.
- После правки кода пересоберите: `docker compose up --build -d`.
  Первая сборка качает Maven-зависимости и pip-пакеты, это несколько минут.

Проверить, что сервисы поднялись:

```powershell
Invoke-RestMethod "http://127.0.0.1:8080/health"
Invoke-RestMethod "http://127.0.0.1:8000/health"
docker compose ps
```

Собрать только API или поднять только его:

```powershell
docker compose build api
docker compose up -d api
```

Локальный запуск через `run-api.ps1`, `run-history.ps1` и `run-bot.ps1`
остаётся рабочим — Docker и скрипты друг другу не мешают, просто не запускайте
оба варианта одновременно: порты 8080 и 8000 окажутся заняты одним из них.

## Тесты

```powershell
mvn test
```

Проверяются: нахождение альта при синхронно набранных друзьях, отделение альта
от близкого друга, сообщение об ошибке при закрытом списке друзей, а также
баллы первичного анализа (молодой «смурф», старый обычный аккаунт, скрытые
данные). Плюс две оффлайн-проверки Python-части:

```powershell
python bot/check_render.py     # лимиты Discord у эмбедов
python history/check_api.py    # ручки сервиса истории
```

`check_render.py` берёт ответы из `target/profile-sample.json` и
`target/detect-sample.json`, а если их нет — встроенные примеры, и проверяет
лимиты Discord. `check_api.py` поднимает uvicorn на свободном порту с временной
базой и проверяет запись, чтение, агрегаты и валидацию всех ручек истории.

## Частые проблемы

| Симптом | Причина |
| --- | --- |
| `Ошибка! Статус-код сервера: 401` в логе | список друзей закрыт настройками приватности |
| «Профиль закрыт настройками приватности» | у профиля `communityvisibilitystate = 1` |
| В консоли `?????` вместо русского | запускайте с `-Dstdout.encoding=UTF-8`, а вывод в файл пишите через `Out-File -Encoding utf8` |
| Бот пишет «Сервер анализа не запущен» | не запущен `ApiServer` или другой `API_BASE_URL` |
| Бот не реагирует на ссылки в чате | не включён Message Content Intent (или стоит `DISCORD_LINK_AUTODETECT=0`) |
| `Could not find or load main class .encoding=UTF-8` | PowerShell разбил `-D...` по `=`; запускайте через `run-api.ps1` или берите аргументы в кавычки |
| `ParserError` в `.ps1` с русским текстом | файл сохранён без BOM; запускайте штатные `run-*.ps1` (они с BOM) или сохраните скрипт как «UTF-8 with BOM» |
| `PROFILE_NOT_FOUND` на красивую ссылку | имя профиля не существует либо Steam API не ответил |
| `env file .env not found` в `docker compose` | в корне проекта нет `.env` — создайте его по разделу «Настройка» |
| Порт 8080 занят при `docker compose up` | уже запущен `run-api.ps1` или другой контейнер; остановите один из них |
| Бот в Docker пишет «Сервер анализа не запущен» | смотрите `docker compose logs api`; адрес должен быть `http://api:8080`, он задан в `docker-compose.yml` |
| Бот не сохраняет историю, в логах «Не удалось сохранить историю» | не запущен сервис `history` (в Docker — `docker compose up -d history`) или не задан `HISTORY_BASE_URL` |
| `/history` отвечает «Сервис истории не подключён» | не задан `HISTORY_BASE_URL` в `.env` — история просто выключена, остальной бот работает |
| `/history` просит SteamID64 | команда принимает только номер или ссылку `.../profiles/…`; красивую `.../id/имя` она не разрешит |
| В `docker compose ps` у `history` статус `unhealthy` | `docker compose logs history`; чаще всего база недоступна или занята другим процессом |

## Структура

```
src/main/java/com/papasmurf/
  Main.java                  CLI-точка входа
  SteamGraphBuilder.java     сбор профилей и списков друзей
  api/                       клиент Steam API и DTO
  analyze/                   первичный анализ профиля (0..100)
  detect/                    поиск «один человек»: признаки, веса, группа
  web/                       HTTP-API: сервер, JSON-ответы, кеш
src/test/java/               тесты анализатора и детектора
bot/                         Discord-бот
bot/Dockerfile               образ бота
history/                     сервис истории: FastAPI + SQLite
history/app.py               ручки /api/v1/history, /api/v1/stats, /health
history/Dockerfile           образ сервиса истории
history/check_api.py         оффлайн-проверка сервиса истории
Dockerfile                   образ Java-API (multi-stage)
docker-compose.yml           три сервиса одной командой
run-api.ps1                  сборка и запуск HTTP-API
run-bot.ps1                  проверка окружения и запуск бота
run-history.ps1              проверка окружения и запуск сервиса истории
```
